# md380tools

## Коротко

md380tools — класичний open-source проект, який започаткував багато кастомних підходів до TYT DMR радіо. Він дуже важливий, бо багато сучасних кастомних прошивок базуються на ідеях, утилітах і змінених адресах, які вперше з’явилися в цьому проекті.

GitHub:
https://github.com/travisgoodspeed/md380tools

## Що робив проект

У перших варіантах проектів такого типу ключовий акцент був не на “повному кастомному stack”, а на:
- фізичному патчінгу прошивки
- плагіні для слоту flash/ROM
- прослуховуванні або змінах доступу до системних параметрів
- розширенні codeplug та функціонального меню
- дозволі використовувати інші параметри у радіо без vendor-обмежень

## Чим він важливий для розуміння crypto

md380tools не є “чисто крипто-проектом”. Він в основному про:
- офсетні патчі в прошивці
- розуміння flash-структури
- побудову мінімально необхідного firmware-патчінгу
- доступ до параметрів радіо, ключів, конфігів і add-ons

Для крипто-стеку важливо те, що в цьому типі проектів дуже часто:
- весь vendor key handling виводиться з “зашитих” місць у flash
- key storage і key selection стають видимішими за рахунок патчів і обхідних інтерфейсів
- шифрування не “зникає”, а просто стає доступнішим для аналізу, модифікації і інтерфейсу

## Чим відрізняється від OEM прошивки

OEM прошивка зазвичай:
- робить vendor key handling і UI закритими
- вбудовує crypto в системному ланцюзі без видимих точок входу
- не показує параметри ключів і не дає простий way to export them

md380tools розбиває цю замкнутість за рахунок:
- патчів до flash/ROM
- підправлення коду для відображення і редагування
- змін меню і ключових карток
- відкриття доступу до функцій, які були приховані початковим vendor build

## Як це впливає на шифрування

У custom firmware цей ефект майже завжди такий:
- ключі більше не є “непорушним vendor-secret”
- UI і фрейм-логіка стають прозорими
- формування keystream і key selection можна відслідковувати у самій прошивці
- етапи “key load → alg select → keystream generation → payload decrypt” стають доступнішими для reverse engineering

## Важливий висновок

md380tools — це не просто “клієнтська прошивка з додатковими кнопками”. Це один із типових прикладів того, як кастомні проекти розкривають і переробляють vendor firmware під відкритий інженерний керований процес.

## Для декодера

Цей проект особливо корисний для того, щоб зрозуміти:
- як flash і codeplug структури взаємодіють з ключами
- де vendor firmware ховає ключі і key id
- як виглядає “patcheable firmware” для DMR радіо
- як інженерний UI і crypto logic відокремлюються від vendor-інтерфейсу
